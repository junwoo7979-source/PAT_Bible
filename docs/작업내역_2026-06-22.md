## 1. 교구별 현황 — 관리 편집 + 동기화

**문제**
- 관리자 교구별 현황 코드가 3개 구현이 뒤엉킨 미완성 상태(저장키·id 불일치, 저장해도 복원 안 됨, 사용자 대시보드가 관리자 값 무시).

**수정**
- 편집 폼: **완료 = 자동 집계(읽기전용)**, **전체 인원 = 관리자 입력**.
- 저장/복원/렌더를 단일 키 `pat_admin_parish_edit`로 일원화, 죽은 코드 제거.
- 사용자 대시보드(`renderParishStatsFromAggregated`)가 관리자 전체 인원을 분모로 사용.
- 변경 감지(`hasChanged`)에 관리자 인원 포함 → 관리자 변경 즉시 대시보드 반영.

## 2. 관리자 ↔ 대시보드 불일치 (기기 간) 해소

**원인**
- 관리자 전체 인원이 `localStorage`(그 기기에만) 저장 → 성도 기기엔 없어 기본값 표시.

**수정**
- 저장 시 **서버 `config.parishTotals`에도 저장**(`saveConfig` 부분 업데이트 지원).
- 모든 기기가 config의 `parishTotals`를 localStorage로 미러링(`applyCloudConfig`) → 서버가 단일 진실 소스.
- 검증: 기기A 저장(150/120/110/30) → 기기B(별도 저장소) 자동 동기화 확인.

## 3. 교구별 현황 = "진도(완료 멤버)" 집계

**문제**
- 등록 인원수를 완료처럼 표시 → 진도 0인데 숫자가 떠 오류로 보임.

**수정**
- `getDashboard`의 `byParish` = **현재 구절을 완료한 멤버 수**(records 기반, 멤버 단위 중복 제거).
- 등록만 하고 미완료면 0. 진도 없으면 0으로 정상 표시.
- 멤버 등록 인원 헤드카운트(`totalMembers`)는 별도 반환(참고).
- 집계 로직 `functions/aggregate.js`로 분리(단위 테스트 완료).

## 4. 교구값 정규화 + 교구 드롭다운

- 가족방 교구 입력: **자유 텍스트 → 드롭다운(1/2/3교구)** (집계 누락 방지).
- 백엔드 `normalizeParish`: 레거시 "1", "1 교구", "일교구" → "1교구"로 정규화해 집계 포함.

## 5. 날짜 → 적용 주차·기간 자동 연동

**문제**
- 관리자 진입 시 `syncAdminVerseFields`가 저장된 옛 주차로 덮어써서 날짜와 어긋남.

**수정**
- 적용 주차는 **항상 기준 날짜에서 파생**(`updateWeekFromDate`)하도록 순서 변경.

## 6. 음성인식 Whisper 교체 + 유사도 100%

**교체**
- Web SpeechRecognition → **브라우저 내장 Whisper(transformers.js)**.
- 모델 `Xenova/whisper-small`(q8). 흐름: 녹음(MediaRecorder) → Whisper 변환 → 기존 채점(`evalVoice`) 재사용.
- 최초 1회 다운로드 후 브라우저 캐시, 음성 화면 진입 시 프리로드.
- 파일: `app/js/whisper-asr.js`(신규), 마이크 버튼 `toggleMic()`→`whisperToggleMic()`.

**정확도 → 유사도 100%**
- 채점에 **자모(음소) 단위 비교**(`jamoNormalize`) 추가: "목자시니"↔"목자신이" 등
  ASR 재음절화·무음 초성 ㅇ 차이를 음소 레벨에서 동일하게 인정 → 90%→**100%**.
- 채점은 음절·발음·자모 유사도 중 최댓값 사용(틀린 낭독은 여전히 낮게 → 검증 유지).
- 테스트(한국어 TTS): 자모 유사도 **100%** 확인.
- 모바일 부담 크면 `whisper-asr.js`의 `WHISPER_MODEL`을 `whisper-base`로 한 줄 변경(자모 채점으로 100% 동일).

## 7. 중대버그 — 홈에서 새로고침 시 관리자 화면으로 튕김

**증상**
- 성도 홈(`s-family`)에서 새로고침 → 관리자 화면(`s-admin`)으로 넘어감.

**원인**
- 시작 화면 결정이 2단계(`determineInitialScreen` 즉시 → `completeAppInitialization` 50ms 뒤 덮어쓰기).
- `completeAppInitialization`이 가족 판정을 `savedFamily.familyId`로 했으나, **`familyId`는 프로필 객체가 아니라 별도 키 `pat_family_id`에 저장** → 조건이 항상 거짓 → 관리자 자격(`pat_admin_id/pw`)이 저장된 기기에서 가족이 있어도 `s-admin`으로 덮어씀.

**수정**
- 가족 판정을 `determineInitialScreen`과 동일하게 "프로필 존재"만으로 → `s-family` 우선.
- 테스트 4/4 통과(가족+관리자→홈, 미동기화가족→홈, 관리자만→관리자, 초기→로그인).
- 파일: `app/js/app-core.js`
